Harsha asked (2026-06-10): learn his Slack writing style and use it for all messages drafted as him from now on. Derived from ~25 hand-typed messages across #teli-signal-house, #nexamortgage, group DMs, and 1:1 DMs.

## Core voice

- **Casual, direct, friendly.** Talks to teammates like friends: "bro", "brother" (stretched for emphasis: "brotherrrr"), "guys", "hey", "hi guys", "hello again".
- **Mostly lowercase**, including "i". Sometimes a capitalized first word (phone autocapitalize) — both are authentic. Names lowercase: "chelle", "jon".
- **Run-on sentences, light punctuation.** Long thoughts = one flowing paragraph, few commas, no formatting. Occasional space before "?" ("bro ?"), doubled marks ("is this right??").
- **Small typos are natural** ("thru", "teh", transposed letters) — don't engineer them, but don't over-polish either. No em-dashes, no bullet lists, no bold headers in hand-typed messages.
- **Indian-English constructions** he genuinely uses: "can you once check it out", "explain me", "from a week" (= for a week), "correct me if i am wrong here".

## Patterns by situation

- **Asking for help:** "can you look at this and give me some insight on how it is supposed to work", "if you dont mind can you explain me...", "jon can we huddle when you are available there a major problem in X which we need to discuss."
- **Status updates:** "i'm making changes to X just to make it streamlined will let you know once done can you try once after its done ?"
- **Apologizing/thanking:** "sorry for the extra work but i tried to do it thru dashboard...", "thank you for the help guys".
- **Short acks:** "sure", "yess", "Okay", "Perfect this solves it".
- **Flows/technical sequence:** plain arrows — "you create a brand -> it needs to get verified -> buy a number ... correct me if i am wrong here."
- **Technical deep-detail** (root-cause writeups, API specs): he pastes polished agent output, often in code blocks. So authentic pattern for technical answers = casual hand-typed intro line + clean technical body. Numbered asks OK there ("could you please: 1. ... 2. ...").

## When to apply

- ANY message drafted to be sent as Harsha: Slack channel replies, thread replies, DMs, group DMs.
- Do NOT apply to: code, commits, PRs, docs, customer-facing formal docs — those stay normal/professional ([[feedback-no-whitelabel-mention-in-bevri]] rules still apply to content).
- A Claude-sounding draft (bold headers, em-dashes, "Short version:") reads as fake — rewrite before drafting on his behalf.
